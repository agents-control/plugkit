# ADR-0003: adapters.yaml semantics the research draft left open

Status: **Accepted** (2026-11-13). Refines UP-ADR-002 §2 and UP-ADR-001 §9.

## Decision

1. **The engine declares a `Spec` once.** Per port: `Default`, `Builtins`, `Memory`, `Plugin`, `Multi`, `Stateful`, `Sensitive`, `Weak`, `Aliases`, built-in `Capabilities`. `Load`, `Check`, `Diff` and `Describe` derive everything from it; no engine-specific branches live in plugkit.
2. **Env form.** `<P>_<PORT>` (upper case) and each alias select the port; values are comma-separated for multi-valued ports. A bare value other than `memory` means `builtin:<value>`, so `WF_STORE=postgres` keeps working. Two env names that disagree, or a port set in the file and in env, are errors. `<P>_MODE` sets the mode only without a file (the file must state it). `<P>_ALLOW_MEMORY` sets `allowMemory` without a file; with a file it must agree with the file's `allowMemory`, otherwise it is an error.
3. **Without a file the mode is `production`.** Secure by default: an engine whose default for a stateful port is `memory` must change that default to a built-in or ship `<P>_MODE=dev` in its dev compose profile.
4. **Conformance is a digest plus a report path.** `require.conformance` (the report digest) cannot be verified alone, so it travels with `require.report`, a path the host reads at boot. `adapters.Dial(ctx, host, spec, file, suites...)` runs `Check` (so boot cannot accept what `adapters check` refuses), then verifies the digest, that every case passed, that the report's manifest digest equals the pinned one, and that the report covers every enabled port with the host's own suite version (a port the host has no suite for cannot be verified). Production refuses a plugin without both fields, at dial and not only in `Check`, or with a report that does not verify; dev degrades it.
5. **Plugin ports are derived.** `plugins[].ports` defaults to the ports whose `use` names the plugin; when set, it must cover them. The host enables only that list intersected with the manifest. Each port's `config` becomes the plugin's settings for that port and is validated against the declared `config_schema` at the handshake; an absent config is `{}`.
6. **Literal secrets are refused.** In `config`, a key ending in `Ref` must hold a reference (`env:`, `file:`, `<resolver>:`); a key that looks like a secret (`secret`, `token`, `password`, `credential`, `apikey`, `private`) without the `Ref` suffix is an error.
7. **Bearer over plaintext is an error in production.** A `credentialRef` with insecure TLS to a non-loopback endpoint is refused in production and a warning in dev.
8. **Plan is `Diff(spec, desired, GET /v1/adapters)`.** Ports compare as sorted selection sets. Flags: `weakening` for memory in production, dev mode replacing production, a `Sensitive` port moving to a plugin or a `Weak` built-in, plaintext to a plugin, a plugin without a conformance report. A port whose selection is unchanged still yields a change when its plugin's config weakens it: plaintext where the running row (`plaintext` in `GET /v1/adapters`) was not, or a dropped conformance report. `data_migration_required` for a `Stateful` port whose selection changes. Hot swap does not exist; apply is a restart, and refusing apply without `--accept-empty-store` belongs to the engine.
9. **Wave-2 additions.**
   - `adapters.EnvNames(spec)` lists every variable the layer reads and `adapters.Environ(spec, os.LookupEnv)` feeds `Load`; `File.First(port)` returns the first selection. Engines keep no env-name lists of their own.
   - `PortSpec.BuiltinConfig["builtin:<name>"]` declares the config keys of each built-in with a kind (`ref`, `string`, `bool`, `number`). On a port served only by built-ins or memory, an undeclared key is a boot error and a declared key of the wrong kind too; when a plugin is also selected, undeclared keys are left to the plugin's `config_schema`.
   - `adapters plan --against url` authenticates with `--token env:NAME` (bearer) and repeatable `--header Name=env:NAME`; values are references only, never literals on the command line. `discovery.Fetch` takes `WithBearer` and `WithHeader` options.
   - A port the embedder serves through a Go option gets a row from `discovery.EmbeddedRow(port, name)` (tier `embedded`), placed with `Document.ReplacePort(port, rows...)`; a multi-valued port keeps its other providers by passing `Document.Rows(port)` along. The adapter file cannot select an embedded adapter, so `Diff` skips any port that has one.
10. **Wave-3 additions** (see ADR-0005). `Spec.Validate` adds the engine's offline rules to `Check`; `acknowledge: [name]` (or `<P>_ACKNOWLEDGE`) lists opt-ins from `Spec.Acknowledgements`, read with `File.Acknowledged`; each port's `config` is also sent in `ManifestRequest.port_config`.
11. **Engine extensions** (see ADR-0007). `extensions.<key>` holds engine-declared sections validated by `Spec.Extensions[key].Schema`, shown in `GET /v1/adapters` only through the engine's checked `Discover` projection and judged by the engine's `Weakening` in `Diff`; `<P>_EXTENSION_<KEY>` is refused in production.
